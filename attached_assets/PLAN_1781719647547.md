## 1. Executive Summary

This plan governs the complete fix and enhancement of the **योग प्रशिक्षक मानदेय उपस्थिति पत्रक** (Yoga Trainer Honorarium Attendance Sheet) module within the Rajasthan Ayurveda Department web application.

The document is an official Rajasthan Government form issued by the **आयुर्वेद विभाग राजस्थान सरकार**, specifically for **आयुष्मान आरोग्य मंदिर (AHWC)** offices. It records monthly attendance and calculates honorarium payments for male and female yoga trainers.

**Cascade must treat this as a surgical fix task** — meaning only the files, components, and logic described in this plan should be touched. No refactoring of unrelated code.

The current system has issues in:
- Column logic (especially columns 4, 5, 6, 7, 8, 9)
- Auto-calculation rules not enforced
- Payment caps not applied
- Column 6 not correctly disabled for female trainers
- PDF output misalignment and broken borders
- Incorrect or missing certification text
- Table grid inconsistencies in both web UI and PDF export

## 3. Root Cause Analysis

### 3.1 Column 4 is Editable
The month/year selector is disconnected from Column 4. Column 4 must be a derived read-only value. Currently treated as a free-text input.

### 3.2 No Gender-Aware Column Logic
Trainer rows do not carry a gender flag. The UI renders the same input for all rows regardless of trainer type.

### 3.3 Columns 7, 8, 9 Not Computed
These are likely plain input fields with no reactive formula binding. Must be converted to computed display fields.

### 3.4 Payment Cap Not Implemented
Column 9 shows raw Column 7 × 250 with no ceiling enforcement.

### 3.5 PDF Rendering Issues
PDF export likely uses direct HTML-to-PDF without fixed table layout. Column widths are not locked, causing border misalignment.

### 3.6 Certification Text Mismatch
The certification paragraph is either hardcoded with wrong text or sourced from a variable never updated to official wording.

## 5. Table Structure Changes

### 5.1 Column 4 — दिवस संख्या

- Source: auto-derived from document-level month/year selector
- Editable: NO — render as static display, not an input element
- Updates: immediately when month/year changes
- Applies to: all rows equally (same value across all rows)
- Leap year logic:
  - Divisible by 4 AND (not divisible by 100 OR divisible by 400) → 29 days in Feb
  - All others → 28 days in Feb

### 5.2 Column 5 — जन सामान्य योग घंटे

- Editable: YES — integer input for all trainer types
- Minimum: 0
- Maximum: value of Column 4 for the current month
- Validation: block values outside 0–Column4 range; show inline error in Hindi
- Type: integer only; reject decimals
- On change: recalculate Column 7 and Column 9 for that row

### 5.3 Column 6 — IEC कार्यक्रम घंटे

**Male trainer (पुरुष योग प्रशिक्षक):**
- Editable: YES — integer input
- Minimum: 0
- Maximum: 2
- Validation: block values > 2; show inline error
- On change: recalculate Column 7 and Column 9

**Female trainer (महिला योग प्रशिक्षक):**
- Editable: NO
- Display: "N/A"
- Internal calculation value: 0
- Styling: disabled appearance

### 5.4 Column 7 — कुल घंटे

- Editable: NO — read-only computed field
- Formula: `Col7 = Col5 + Col6` (Col6 = 0 for female)
- Updates: immediately on any change to Col5 or Col6

### 5.5 Column 8 — दर प्रति घंटा

- Column heading: **दर ₹250/-**
- Cell value: **₹250/-** (fixed for all rows)
- Editable: NO — render as static label
- ₹ symbol: use Unicode ₹ (U+20B9) directly in source

### 5.6 Column 9 — कुल भुगतान राशि

- Editable: NO — read-only computed field
- Base formula: `Col9 = Col7 × 250`
- Cap rules:
  - Male: if Col9 > 8000, set Col9 = 8000; set `isCapped = true`
  - Female: if Col9 > 5000, set Col9 = 5000; set `isCapped = true`
- Display format: `₹[amount]/-` (e.g., ₹3,250/-)
- Updates: immediately when Col7 changes

## 7. Auto Calculation Rules

### 7.1 Trigger Events

| Event | Triggered Recalculations |
|-------|--------------------------|
| Month/Year changes | Column 4 for all rows; re-validate Column 5 for all rows |
| Column 5 changes (any row) | Column 7, Column 9 for that row |
| Column 6 changes (male row) | Column 7, Column 9 for that row |
| New trainer row added | Column 4 auto-filled; Column 6 set based on gender |

### 7.2 getDaysInMonth Logic

```
getDaysInMonth(month, year):
  IF month IN [1, 3, 5, 7, 8, 10, 12] → return 31
  IF month IN [4, 6, 9, 11] → return 30
  IF month == 2:
    IF (year % 4 == 0 AND year % 100 != 0) OR (year % 400 == 0):
      return 29
    ELSE:
      return 28
```

### 7.3 Column 7 Formula

```
IF gender == MALE: Col7 = Col5 + Col6
IF gender == FEMALE: Col7 = Col5 + 0
```

### 7.4 Column 9 Formula with Cap

```
rawPayment = Col7 × 250
cap = (gender == MALE) ? 8000 : 5000

IF rawPayment > cap:
  Col9 = cap
  isCapped = true
ELSE:
  Col9 = rawPayment
  isCapped = false
```

### 7.5 Calculation Order (Must Not Deviate)

1. Column 4 ← getDaysInMonth(selectedMonth, selectedYear)
2. Column 5 ← user input (validated against Column 4)
3. Column 6 ← user input for male (validated max 2); 0 for female
4. Column 7 ← Col5 + Col6
5. Column 8 ← fixed 250 (no calculation)
6. Column 9 ← min(Col7 × 250, genderCap)
